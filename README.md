# AI Suspicious Transaction / AML Detection System

A decision-support project for identifying transactions that may warrant
anti-money-laundering (AML) investigation. It includes a supervised Random
Forest classifier, two unsupervised anomaly detectors, validation-only
threshold selection, evaluation reports, a command-line interface, and a
Streamlit dashboard.

> **Important:** an alert means "suspicious transaction detected - investigate."
> It does not confirm money laundering or establish criminal activity.

## Problem statement and objectives

The IBM AML dataset has a highly imbalanced laundering label. The project aims
to:

- learn a reproducible supervised baseline and unsupervised anomaly models;
- rank transactions for human investigation;
- report precision-recall-oriented metrics alongside confusion counts;
- keep training, validation, and final test data separate; and
- make training, evaluation, and review reproducible through CLI and dashboard
  workflows.

## Dataset

Use the original IBM AML transaction CSV with these columns:

`Timestamp`, `From Bank`, `Account`, `To Bank`, `Account.1`,
`Amount Received`, `Receiving Currency`, `Amount Paid`, `Payment Currency`,
`Payment Format`, and `Is Laundering`.

Place the dataset in `data/raw/` or set `AML_DATASET_PATH` to its path. No
transactions are generated by this project. The default CLI training workflow
uses a reproducible uniform sample of at most 500,000 real rows, selected in
chunks to avoid loading a multi-gigabyte CSV into memory. This preserves the
dataset's approximate class prevalence. Use `--max-rows` to change this cap.
The evaluation numbers then describe the sampled holdout, not the entire
dataset.

The currently configured `HI-Medium_Trans.csv` was inspected chunk-by-chunk:
31,898,238 rows, 11 columns, 35,230 positive labels (0.110445% prevalence),
and 31,863,008 negative labels. These are dataset counts, not model results.

The original dataset is excluded by `.gitignore`; do not commit it or any
confidential transaction data.

## Architecture

```text
main.py
├── src/data_loader.py             dataset discovery, chunking, uniform sampling
├── src/feature_engineering.py     deterministic, target-independent features
├── src/preprocessing.py           train-fitted imputers, scaling, encoding
├── src/train_random_forest.py     supervised model + validation threshold
├── src/train_isolation_forest.py legitimate-only anomaly model + threshold
├── src/train_autoencoder.py       batched legitimate-only reconstruction model
├── src/evaluation.py              binary and ranking metrics
├── src/threshold_optimization.py  validation threshold comparison
├── src/prediction.py              consistent scoring and investigation report
├── src/visualization.py           confusion, ROC, PR, threshold, comparison plots
└── dashboard/                     Streamlit overview and review pages
```

Artifacts are written under `models/` and `results/`. These generated files are
ignored by Git by default.

## Training

```bash
python main.py train-rf
python main.py train-if
python main.py train-ae
python main.py train-all
```

Each training command accepts `--dataset`, `--max-rows`, `--test-size`,
`--validation-size`, and `--random-state`. Random Forest and Isolation Forest
also accept `--estimators`; the autoencoder accepts `--epochs`, `--batch-size`,
`--latent-dimension`, `--reconstruction-loss`, `--score-method`, and
`--normal-validation-quantile` (default `0.999`, targeting a 0.1% false-positive
rate on normal validation transactions). Quantiles `0.98`, `0.99`, `0.995`,
and `0.999` correspond to nominal normal-only false-positive targets of 2%,
1%, 0.5%, and 0.1%; the saved threshold and score scale are model artifacts.
`train-all` accepts shared `--max-rows`, `--estimators`, `--epochs`,
`--batch-size`, `--contamination`, `--latent-dimension`, `--score-method`, and
`--normal-validation-quantile` options, and loads the real-data sample only
once.

Training splits sampled rows into training, validation, and test partitions.
Preprocessing is fitted on training data only. Random Forest is trained on the
training partition; Isolation Forest and the autoencoder are trained on the
legitimate rows in that partition. The autoencoder cutoff is the configured
quantile of scores from normal validation rows only; its score must strictly
exceed that saved cutoff to be flagged. The default Autoencoder uses an 8-unit
latent representation and feature-normalized MAE reconstruction scoring. Its
per-feature residual scales and feature order are saved in the metrics artifact
and verified against the fitted preprocessor at inference. The saved test
partition is used only for final evaluation.

## Evaluation

```bash
python main.py evaluate
```

Evaluation recalculates metrics from saved held-out predictions and refreshes
reports and figures. Metrics include precision, recall, F1, F2, ROC-AUC,
average precision, false-positive and false-negative rates, confusion counts,
and total alerts. Average precision and precision-recall curves are emphasized
because the positive class is rare.

Outputs include model-specific JSON and CSV files in `results/metrics/`,
held-out predictions in `results/predictions/`, and confusion, ROC, PR,
threshold comparison, and model comparison plots in `results/plots/`.

## Prediction

Batch scoring from the CLI:

```bash
python main.py predict \
  --model random_forest \
  --input path/to/transactions.csv \
  --output results/predictions/uploaded_results.csv
```

Supported model names are `random_forest`, `isolation_forest`, and
`autoencoder`. An optional `--threshold` overrides the model's saved threshold
for this scoring run. The report includes a model score, predicted class,
threshold, alert status, and a transaction identifier when supplied (otherwise
the input-row position). New categorical values are supported; missing expected feature columns are
imputed using the fitted training pipeline. Unrecognized-only input files are
rejected with an actionable error.

## Dashboard

```bash
source .venv/bin/activate
streamlit run dashboard/app.py
# Alternative CLI launcher:
python main.py dashboard
```

The dashboard uses a shared dark financial-crime intelligence theme and
sidebar navigation for Executive Overview, Single Transaction, Transaction
Analysis, Alert Investigation, Performance, Metric Charts, Model Information,
and Data Exploration. Transaction-analysis and investigation pages support
filtering, sorting, detail inspection, pagination, and CSV export. Analyst
status and notes remain in the current Streamlit session only. The
single-transaction page derives required fields and categorical choices from
the selected model's saved preprocessor. IBM Payment Format is used as
transaction type; origin/destination accounts are context only because the
models exclude account identifiers. The source dataset has no before/after
balance columns, so those unsupported fields are not requested. The dashboard
reports missing datasets and artifacts without treating them as successful
predictions.

## Results

### Actual run

The configured 31,898,238-row dataset was uniformly sampled to 500,000 real
rows using seed 42. Each model used 350,000 training rows, 75,000 validation
rows, and 75,000 final test rows; the two anomaly models fitted on the 349,587
legitimate rows within the training partition. The Random Forest and Isolation
Forest remain from that same split. The Autoencoder was then retrained with a
latent dimension of 8, early stopping (26 of 50 epochs), MSE training loss,
feature-normalized MAE scoring, and a q99.9 normal-only validation threshold.
The architecture, score, and quantile were selected using validation data only;
the test split was used only for the final evaluation. The run commands were:

```bash
python main.py train-ae --max-rows 500000 --epochs 50 --batch-size 256 --latent-dimension 8 --normal-validation-quantile 0.999 --score-method feature_normalized_mae
python main.py evaluate
```

| Model | Threshold | Precision | Recall | F1 | F2 | ROC-AUC | Average precision | FPR | FNR | TN / FP / FN / TP | Alerts |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Random Forest | 0.04000 | 0.1142 | 0.5682 | 0.1901 | 0.3165 | 0.8680 | 0.2690 | 0.00518 | 0.4318 | 74,524 / 388 / 38 / 50 | 438 |
| Isolation Forest | 0.03387 | 0.0000 | 0.0000 | 0.0000 | 0.0000 | 0.5273 | 0.00119 | 0.00439 | 1.0000 | 74,583 / 329 / 88 / 0 | 329 |
| Autoencoder | 4.20555 | 0.0000 | 0.0000 | 0.0000 | 0.0000 | 0.5757 | 0.00127 | 0.00076 | 1.0000 | 74,855 / 57 / 88 / 0 | 57 |

This holdout contained 88 laundering labels. Random Forest had the strongest
average precision (0.2690) and F2 (0.3165). Isolation Forest and the
Autoencoder detected no laundering rows at their saved thresholds. The
Autoencoder's test ROC-AUC was 0.5757 and average precision was 0.001270.
Compared with the prior latent-26, MSE, q99.5 baseline (ROC-AUC 0.5608,
average precision 0.001280, 379 alerts), the candidate raised ROC-AUC slightly
and reduced alerts, but average precision was slightly lower and recall remained
zero. This is not a demonstrated improvement in laundering detection.

#### Validation threshold tradeoff

Each cutoff below is computed from normal validation scores only; the reported
validation metrics use the full validation labels for comparison. The selected
production artifact remains calibrated at q99.9.

| Normal quantile | Threshold | Alerts | Validation FPR | Precision | Recall | F2 |
|---|---:|---:|---:|---:|---:|---:|
| 98.0% | 2.68529 | 1,501 | 2.001% | 0.133% | 2.273% | 0.00540 |
| 99.0% | 2.96397 | 752 | 1.001% | 0.266% | 2.273% | 0.00906 |
| 99.5% | 3.19482 | 376 | 0.501% | 0.266% | 1.136% | 0.00687 |
| 99.9% | 4.20555 | 76 | 0.100% | 1.316% | 1.136% | 0.01168 |

The selected q99.9 configuration maximized validation F2 among the evaluated
normal-only quantiles, but it detected only 1 of 88 validation positives.
Feature-normalized MSE had better validation ranking metrics (ROC-AUC 0.6377,
average precision 0.001571), but did not detect a laundering row at the q99.5
baseline. Latent dimensions 26 and 16 and a Huber/dropout/L2 variant had lower
validation ranking metrics than the latent-8 MSE-trained model. This small
validation signal is unstable and is not evidence of reliable detection.

#### Test score distributions

absolute residual on normal validation rows, with a small floor; higher scores
are more anomalous. The normal class has a very heavy upper tail, while the
maximum laundering score (2.09040) is below the calibrated threshold (4.20555).

The prior investigation found the strongest raw reconstruction-error
contributors among normal rows included `Amount_Difference`, `Hour`, and
`Amount Paid`; `Amount_Ratio` was also prominent. The existing features already
include log amounts as well as raw amounts, ratios, and differences. Numeric
and one-hot categorical dimensions contributed comparably overall, so
categorical dimensionality alone did not explain the overlap. No amount
transformation was changed without validation evidence.

These are results from one uniformly sampled holdout, not guarantees about
other samples or operational data. Do not treat Autoencoder alerts or
non-alerts as determinations. The detector remains weak and is not suitable as
a standalone AML decision system.

## Limitations and future improvements

- A uniformly sampled dataset is used for training by default; results should
  be interpreted in the context of that sample and the specific label quality.
- Synthetic or historical benchmark data may not represent current financial
  behavior or the operational cost of reviewing alerts.
- Account identifiers are excluded from model features; entity and network
  behavior are not modeled.
- Thresholds optimize validation metrics, not institution-specific capacity,
  costs, or regulatory requirements.
- A production deployment would need drift monitoring, access controls,
  privacy review, analyst feedback, audit trails, and institution-approved
  escalation procedures.

Potential future work includes temporal validation, graph/network features,
cost-sensitive threshold policies, drift monitoring, model calibration, and
secure integration with an analyst case-management system.
